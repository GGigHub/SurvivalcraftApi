# 界面

代码目录：`scenes/ui/`，需要逻辑时用 C# 挂在 Control 上。布局不要写在玩法模块里。

原项目用自研 Widget 树，约有这些屏幕：加载、加载失败、主菜单、开始游戏、新世界、世界选项、游戏、玩家列表、玩家、设置（画面、声音、控制、界面、性能、兼容）、模组管理、模组设置、图鉴、合成谱、帮助、社区、外部内容、用户、键位、手柄、VR 控制器、相机布局、内容管理。另有背包、合成、熔炉、箱子等游戏内界面和各类对话框。

## 必须

- 上列屏幕都要有入口，不能只做主菜单加一个游戏画面。
- 界面读 C# 状态，不自己保存第二份背包或设置。
- 准星、快捷栏、生命饥饿留在游戏内 HUD，不用网页。
- 文本输入（告示牌、存储体、命名）用 Godot 的文本控件。中文输入法要在 Windows 上能打字。
- 游戏内暂停时鼠标可见，关闭界面后恢复捕获。

## 禁止

- 把旧 Widget 类逐个翻译成同名 Control。
- 用 HTML、WebView 或 Label3D 做菜单。
- 在 `Boot.tscn` 上堆玩法 UI。

## 完成标准

不改代码就能从主菜单进入一局、打开背包和设置、看图鉴和帮助、管理模组入口。缺的屏幕不能隐藏菜单项来假装完成，除非本文件记载该项已从原游戏确认不存在。
