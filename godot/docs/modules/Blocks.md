# 方块

代码目录：`scripts/Blocks/`。

原项目约有三百个方块源文件。每个方块自己往地形里写顶点。重做后形状种类有限，具体方块用数据选形状。

## 必须

- 先登记形状，再填方块表。首批形状至少包括：空、实心、半砖、楼梯、十字植物、火把状、门、活板门、栅栏、楼梯之外的薄片（雪层、地毯一类）、液体。缺形状时先改本文件，禁止在某个方块类里私自提交顶点。
- 方块数据至少有：稳定整数 id、名字、形状、贴图、硬度、是否透明、是否碰撞、掉落、光照等级。
- 原游戏里玩家能放置或遇到的方块都要有 id。工具、食物、电路块、家具块可以先占 id，行为分到对应模块，但不能从 id 表消失。
- 挖掘和放置走同一入口。放置失败不能写出半个格子。
- 模组只能选用已登记形状或一个 glTF 模型，不能提交自定义顶点。见 [Mods.md](Mods.md)。

## 禁止

- 一个方块一个 Godot 场景。
- 用类继承树复制旧的 `Block.cs` 体系。特殊行为用小的 C# 钩子，挂在方块 id 上。
- 为了赶进度删掉「不重要」的方块而不写进本文件的缺口列表。

## 缺口

形状都已有网格。火把、楼梯、半砖和木栅栏在运行时读原版 Collada，节点矩阵换算到格子里。模型贴图若落在图集第一格，会平移到该方块自己的贴图槽；火把模型的坐标已经写在图集上，不再平移。火把火苗那一块顶点第二套 UV 为全亮。还没有按原版方块表填满几百种方块，也没有硬度。液体只有会流动的水和岩浆，见 [Fluids.md](Fluids.md)。

## 完成标准

方块表覆盖原游戏的可放置方块和自然生成方块。挖和放会更新地形与光照。形状超出登记表时，代码无法通过编译或在加载时报明确错误。
