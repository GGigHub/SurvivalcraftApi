# API 1.45 向下兼容支线

## 定位

本支线从已验证的 API 1.9.3.1 联机提交 `72653e56` 切出，先兼容中文社区中已锁定的三个经典目标：DayZ 2.2.3.0、枪械 2.8，以及依赖枪械 2.8 的黑蝎 2.8。兼容代码必须是附加式、可测试、可归因的，不能以降低当前 API 校验或吞掉异常为代价。

第一阶段的“兼容”仅表示旧模组能够稳定加载、创建世界、退出和重进。模组新增实体、武器、容器或生存系统的多人同步属于后续独立里程碑。

## 已知基线

- DayZ：目标 API 1.45 / SC 2.3；解决 6 组类替换和公告框后，因缺少 `Game.SubsystemSeasons` 返回主菜单，同时存在大量旧 crafting ID 和字段错误。
- 枪械 2.8：目标 API 1.45 / SC 2.3；进入玩家路径后出现 `IsExplosionTransparent`、`ModsManageContentScreen.GetDecipherStream(Stream)`、`CraftingRecipesManager.Recipes` 和 `gmitems` 等断层，随后发生 Mono `SIGSEGV`。
- 黑蝎 2.8：资源扩展包，与枪械 2.8 联用；当前在 `Game.SubsystemWorldChest` VTable 建立阶段失败，并引用缺失的黑蝎方块/配方标识。
- API 1.9 现代语料仍为保护门禁：9 个模组、12 个单体/组合用例必须持续全绿。

权威输入是 `tests/android-classic-mod-corpus/manifest.json` 与 `lock.json`；兼容判断按包名、包内 API 版本和 SHA-256 记录，不依赖易漂移的下载文件名。

## 实施原则

1. 先做 A/B：同一哈希包分别在未加入联机核心的 API 1.9.3.1 基线和本支线运行，区分上游 API 断层、联机回归与模组自身缺陷。
2. 优先增加保持旧签名的薄适配器、只读别名或确定性数据迁移；禁止改变当前 API 的公开语义来迎合单个旧包。
3. 包特定修复必须精确匹配已审计身份，并在未知版本上 fail closed；通用兼容面必须有独立单元测试证明不会影响 API 1.9 模组。
4. 不用空 `catch`、忽略类型加载失败或禁用 Game.log 门禁伪造成功。原生崩溃必须通过消除触发条件解决，不能由测试脚本掩盖。
5. 自动测试继续只使用独立 Android 测试包和数据目录；Windows 游戏不得在前台启动。

## 里程碑

### C0：可复现 A/B 与断层清单

- 为 API-only 基线和兼容支线使用同一清单、锁文件、设备动作与日志审计。
- 输出每个目标的缺失成员、类型加载、XDB/crafting ID、资源冲突和原生退出证据。
- 将失败分类为通用 API 断层、模组包缺陷或联机分支差异。

### C1：枪械运行时兼容

- 从最早的缺失成员开始逐个增加最小兼容面。
- 在到达 `Player` 后保持进程稳定，验证世界退出、重进和 Game.log。
- 黑蝎测试在本阶段继续作为依赖组合观察项。

### C2：DayZ 数据与子系统兼容

- 区分真正缺失的生产子系统与旧模板/XDB 名称。
- 为旧 crafting ID、字段和项目模板建立显式迁移或兼容映射。
- 在自定义主菜单、公告和世界生命周期上保留语义自动化。

### C3：黑蝎组合兼容

- 在枪械稳定后处理 `SubsystemWorldChest` 与黑蝎资源/方块标识。
- 验证组合加载顺序、类替换选择、容器/物品注册和重复冷启动。

### C4：联机适配评估

- 先枚举每个模组的权威状态与副作用，再决定通用同步能力或包专用适配器。
- 没有第二客户端、状态探针和断线重连证据前，不宣称模组玩法支持联机。

## 每次提交的门禁

- `Test-Multiplayer.ps1 -Mode fast` 全绿。
- `ReleaseContractTests` 全绿。
- 9 模组 API 1.9 Android 矩阵 12/12 全绿。
- 受影响经典模组用例必须运行并保存结构化结果；预期失败只能保留在观察性用例中。
- 测试结束后 Android 自动测试进程、Mods、Worlds 均为空，设备电源设置恢复。

## 首个开发动作

实现一个不启动桌面窗口的 API-only A/B 入口，复用经典语料清单和 Android 语义桥。先生成机器可读的兼容断层账本，再选择第一个最小、可验证的兼容垫片；在账本完成前不批量添加猜测性旧 API。
