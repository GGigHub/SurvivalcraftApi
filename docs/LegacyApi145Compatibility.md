# API 1.4–1.8 分层向下兼容支线

## 定位

本支线从已验证的 API 1.9.3.1 联机提交 `72653e56` 切出，建立覆盖 API 1.4–1.8 的分层兼容能力。兼容代码必须是附加式、可测试、可归因的，不能以降低当前 API 校验或吞掉异常为代价。

枪械 2.8 的首个生命周期里程碑已经完成，当前最高优先级转为 DayZ。黑蝎 2.8 是单人剧情附加包，按用户决定仅保留为观察样本，不做包专用兼容；它所依赖的枪械公共能力仍属于主线。

第一阶段的“兼容”仅表示旧模组能够稳定加载、创建世界、退出和重进。模组新增实体、武器、容器或生存系统的多人同步属于后续独立里程碑。

## 已知基线

- DayZ：目标 API 1.45 / SC 2.3；解决 6 组类替换和公告框后，因缺少 `Game.SubsystemSeasons` 返回主菜单，同时存在大量旧 crafting ID 和字段错误。
- 枪械 2.8：目标 API 1.45 / SC 2.3；原始基线在进入玩家路径后因旧字段、旧方法、旧物品 ID 和运行时数据断层发生 Mono `SIGSEGV`。当前宿主通过精确包/程序集哈希锁定的内存适配完成新世界与重进，并在两次进入中通过弹道创建/移除探针；Game.log 为 0 错误、0 警告。
- 黑蝎 2.8：单人剧情资源扩展包，与枪械 2.8 联用；当前仅记录 `Game.SubsystemWorldChest` VTable 等观察证据，不进入修复或验收门禁。
- API 1.9 现代语料仍为保护门禁：9 个模组、12 个单体/组合用例必须持续全绿。

权威输入是 `tests/android-classic-mod-corpus/manifest.json` 与 `lock.json`；兼容判断按包名、包内 API 版本和 SHA-256 记录，不依赖易漂移的下载文件名。

模组包与包内 DLL 始终是只读输入。枪械适配只在宿主确认包 SHA-256 `1b4529c8db2af29e0eb14fc570ab3ab7ff8440c10261cbdcb2d14b29bd703b28` 和程序集 SHA-256 `fcd878f569ac4c825402c15d0ffc0af2a5df6e12ec7809b01969b360aa013559` 后，对已解码的内存副本应用确定性迁移；未知哈希拒绝进入包专用路径。

机器可读断层账本是 `tests/legacy-api-compatibility/ledger.json`。兼容层按以下四档推进：

1. API 1.9：原生路径，禁止程序集重写。
2. API 1.8：公共薄垫片；仅对 1.8.1 之前的已知旧签名做精确成员引用迁移。
3. API 1.7：加载器与成员桥，仍只处理有历史证据的确定断层。
4. API 1.4–1.6：按精确断层或哈希锁定包适配；未知成员保持失败关闭。

## 实施原则

1. 同一哈希包在已记录的 API 1.9.3.1 失败基线与本支线对比，区分上游 API 断层、联机回归与模组自身缺陷。
2. 优先增加保持旧签名的薄适配器、只读别名或确定性数据迁移；禁止改变当前 API 的公开语义来迎合单个旧包。
3. 包特定修复必须精确匹配已审计身份，并在未知版本上 fail closed；通用兼容面必须有独立单元测试证明不会影响 API 1.9 模组。
4. 不用空 `catch`、忽略类型加载失败或禁用 Game.log 门禁伪造成功。原生崩溃必须通过消除触发条件解决，不能由测试脚本掩盖。
5. 自动测试继续只使用独立 Android 测试包和数据目录；Windows 游戏不得在前台启动。
6. `Test-ModBinaryCompatibility.ps1` 在上机前只读解码 API 1.9 模组并用 Mono.Cecil 对照当前宿主解析类型和成员引用；任何未解析引用都会在设备启动前失败。

## 里程碑

### C0：分层契约与断层账本（已完成）

- API 1.4–1.8 四档策略、目标优先级和失败关闭规则均已机器化。
- 全量 DLL 扫描证明现代语料不引用首批旧签名；枪械精确引用旧解密方法和旧配方 getter。
- 首批三个断层均有历史签名、迁移策略、实现状态和独立 L0 测试。

### C1：枪械运行时兼容（已完成）

- 已恢复 `Block.IsExplosionTransparent` 的字段形状及爆炸语义。
- 已恢复 `ModsManageContentScreen.GetDecipherStream(Stream)` 转发入口。
- 对 API 1.8.1 之前 DLL 中旧 `CraftingRecipesManager.Recipes` 返回签名做等长元数据名称补丁，转到只读兼容视图；不解析整份旧程序集，现代 `List` getter 保持不变。
- 仅对精确哈希匹配的枪械程序集应用 15 个已登记迁移标记，宿主负责旧枪械数据、配方、地图初始化和弹道更新；原始模组包及 DLL 不修改。旧单参数粒子调用会在内存中迁移到独立兼容入口，避免与 API 1.9 的 Harmony 按名称补丁形成重载歧义。
- Android `world-reentry-pad` 已完成新世界和一次重进，两次均验证 21 组枪械数据、21 个枪械方块、113 个枪械相关方块、51 个配方、4 种光剑颜色和 397 个动画步骤。
- 两次世界进入均完成弹道创建、更新、移除与回调探针，无更新异常；运行日志为 0 错误、0 警告。
- 证据：`TestResults/android-mod-matrix/legacy-firearms-double-hash-final/summary.json`。
- 黑蝎不参与本阶段修复和通过标准。

### C2：DayZ 数据与子系统兼容

- 当前活动里程碑。先对 DayZ 的宿主引用和 XDB 模板做只读盘点，再从首个确定失败点 `Game.SubsystemSeasons` 开始收敛。
- 区分真正缺失的生产子系统与旧模板/XDB 名称。
- 为旧 crafting ID、字段和项目模板建立显式迁移或兼容映射。
- 在自定义主菜单、公告和世界生命周期上保留语义自动化。

### C3：联机适配评估

- 先枚举每个模组的权威状态与副作用，再决定通用同步能力或包专用适配器。
- 没有第二客户端、状态探针和断线重连证据前，不宣称模组玩法支持联机。

## 每次提交的门禁

- `Test-Multiplayer.ps1 -Mode fast` 全绿。
- `ReleaseContractTests` 全绿。
- 9 模组 API 1.9 Android 矩阵 12/12 全绿；经典 API 1.9 三包还必须通过只读二进制解析和世界重进回归。
- 枪械用例保留新世界、重进和功能探针的结构化结果；C2 起当前受影响的 DayZ 用例必须运行并记录新增断层，黑蝎不运行。
- 测试结束后 Android 自动测试进程、Mods、Worlds 均为空，设备电源设置恢复。

## 当前开发动作

对锁定的 DayZ 包执行只读程序集/XDB 盘点，将 `SubsystemSeasons`、旧 crafting ID、字段和项目模板差异拆成可独立验证的账本项；随后在独立测试机后台运行 `dayz-subject`，每轮只处理结构化日志中的首个确定断层。整个过程不修改任何模组文件，也不得弹出 Windows 游戏窗口。
